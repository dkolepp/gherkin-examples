What this means for shared feature files

godog and pytest-bdd use Cucumber's official parser at its newest version, so they read any valid Gherkin. behave writes its own parser, which covers Gherkin 6 and Rule tags but misses some smaller syntax. If one set of .feature files must run in all three, avoid:

  • Doc strings fenced with ```. Use """.
  • Media types on doc strings ("""json). Only godog lets step code read them.
  • A plain Scenario: with Examples. Write Scenario Outline:.
  • Description text under Examples:. Name the Examples block instead.
  • \n or \\ in table cells, and \"\"\" inside doc strings.
  • A step with both a doc string and a table (Gherkin 42 only).

The shop example in this repo already stays inside that subset. Tag filtering differs on each command line, see Running by tag.

How Gherkin has changed

Gherkin is versioned through Cucumber’s parser package, which bumps its major version often (it is at 42). Most bumps are internal. These are the ones that changed what you can write in a feature file:

  1. 3 · 2015–16Table cell escapes (\| \n \\); doc string media type.
  2. 4 · 2016Empty feature files and incomplete outlines allowed.
  3. 5 · 2017–18Parser option for a default language; media type carried through to test runners.
  4. 6 · 2018Big one. Rule: (with its own Background), Example as a synonym for Scenario, and a plain Scenario can carry Examples.
  5. ≤ 10 · 2020``` accepted as an alternative doc string delimiter (exact version unconfirmed).
  6. 18 · 2021Tags on Rule, inherited by its scenarios.
  7. 19 · 2021Experimental Markdown feature files (.feature.md). Not tested here.
  8. 31 · 2025Comments allowed inside descriptions.
  9. 42 · 2026A step may have both a doc string and a data table. Newest major (42.0.1, Aug 2026).

behave doesn’t follow these version numbers. Its 1.2.7 release added “Gherkin v6” support (Rule, the new synonyms); 1.3.x carries that forward.

Method and sources

  • 28 syntax probes plus 2 tag-filter probes, one small .feature file each. Every tool ran each file with a catch-all step that logged the step text, table and doc string it received. A script then compared the log with the expected result.
  • Version history: cucumber/gherkin CHANGELOG. Rule Background and Examples tags/descriptions aren’t dated there, so the probes confirmed they parse in v42.
  • behave 1.2.7 release notes (Gherkin v6 support).
  • cucumber/godog; its go.mod pins gherkin/go/v42.
  • Not tested: Markdown feature files (.feature.md), and per-language keyword quirks beyond French.
